# Проверка согласия пациента с ЭЦП

Дата: 30.09.2026, время Asia/Qyzylorda (UTC+05:00).

## Реализованный сценарий

В карточке пациента врач подготавливает неизменяемый PDF, открывает его для ознакомления пациента и запускает подписание через NCALayer или QR/eGov Mobile. Подписание согласия не использует сеанс входа врача в SIGEX и не меняет учётную запись врача.

Документ, CMS и результаты проверки хранятся зашифрованно. Статус «Подписано ЭЦП пациента» появляется только после проверки SIGEX, совпадения ИИН и точного содержимого PDF. Отдельно отображается обычное согласие, зафиксированное врачом. Доступны история, исходный PDF, CMS и отзыв согласия.

`CONSENT_SIGNATURE_REQUIRED=false` сохраняет ручное согласие. При `true` API и worker требуют действующую подписанную запись в БД; одного статуса в карточке недостаточно. Отзыв отменяет ожидающие попытки. Поздний ответ QR, истечение срока, отмена или выход инициировавшего врача из кабинета не активируют согласие.

## Результаты

- Backend: **99 тестов пройдено**, включая миграцию с сохранением старых данных, зашифрованное хранение, точность PDF, несовпадение ИИН, чужую сессию, отмену, отзыв, истечение срока, logout и повторную проверку политики в worker.
- Frontend: **9 тестов пройдено**, включая передачу точных байтов PDF, параметры личной ЭЦП, отмену NCALayer и сохранение прежнего контракта авторизации врача.
- Production-сборка Vue и Docker-сборки API/worker/UI завершены успешно.
- В отдельной локальной PostgreSQL medhub применена миграция `0003`; перед ней сохранена резервная копия.
- PDF проверен рендерингом: одна страница A4, UMC, читаемая кириллица, идентификатор и версия документа.
- В браузере на синтетическом пациенте проверены подготовка PDF, блокировка подписи до ознакомления, получение настоящего QR SIGEX, восстановление ожидающей попытки после возврата к карточке и отмена. Некорректная CMS отклонена без изменения статуса согласия.
- Реальный SIGEX возвращает HTTP 200 и при ошибках CMS. Проверено, что приложение анализирует JSON и не принимает такой ответ за успех.
- Проверка подготовленных коммитов не обнаружила секретов; пользовательские документы, конфигурация, аудио и артефакты проверок не включены в Git.

## Развёртывание

На `https://medhub.ych.kz/` установлен релиз `20260930-7`. API и worker работают как systemd-сервисы. Перед миграцией создана копия `medhub-before-migration-20260930-093658.dump` в защищённом каталоге резервных копий сервера. Проверены отдельная БД medhub, версия схемы `0003`, RLS и отсутствие доступа ролей `anon`/`authenticated` к таблицам согласий.

После обновления подтверждены HTTPS health, новые маршруты API, соответствие собранного JS опубликованному, ответ 401 при запросе PDF без авторизации и доступность соседнего сайта. Политика на сервере: `SIGEX_ENABLED=true`, `CONSENT_SIGNATURE_REQUIRED=false`.

Дополнительная проверка живого локального PostgreSQL/API подтвердила неизменность PDF, совпадение байтов NCALayer с сохранённым документом и отказ в повторной отправке подписи после отмены.

## Граница проверки

Успешное подписание настоящей ЭЦП владельца, подпись на телефоне пациента и доступ SIGEX к существующему закрытому подписанному документу не подтверждены без участия владельца сертификата. Автотесты этих успешных сценариев используют ответы согласно официальному контракту. При любой ошибке реальной проверки согласие остаётся неподписанным.

Точный контракт, источники и ограничения: [SIGEX и согласие пациента](sigex-patient-consent.md).
