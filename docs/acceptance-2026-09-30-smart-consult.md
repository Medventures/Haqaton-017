# Smart Consult: проверка 18 требований

Дата: 30.09.2026, часовой пояс Asia/Qyzylorda (UTC+05:00).

Этот протокол относится к переходу от Anamio к Smart Consult и новым правилам приёма. Он дополняет [предыдущую проверку Anamio](verification-2026-09-30.md), а не переносит её результаты на обновлённый интерфейс. Материалы пациента из фотографии используются только как образец структуры бланка; проверки выполняются на синтетических данных.

**Локальная приёмка завершена:** полный набор backend — **74 теста прошли**, frontend — **4 теста прошли**, Docker-сборка успешна. Дополнительно пройдены **19 живых проверок** с PostgreSQL, двумя врачами и примером МИС. В браузере на экране **1440 × 1000** пройден сценарий от поиска пациента до проверки консультации и открытия PDF. Загруженное синтетическое аудио длительностью 57 секунд обработано реальными OpenAI ASR и LLM: получена 21 реплика, определены две роли, заполнены поля и предварительное заключение ИИ.

Дополнительно проверен экран **390 × 844**: горизонтального переполнения нет, логотип, навигация и светлая вёрстка сохранены. ФИО врача длиной 105 символов полностью отображается на обоих экранах. Обновление опубликовано на https://medhub.ych.kz/ в релизе `20260930-6`. Ниже результаты браузера отделены от автоматических проверок.

## Дополнительные проверки

- Миграция [0002](../backend/migrations/versions/0002_shared_patients_visit_lifecycle.py) сохраняет существующие карточки и их данные. Общий реестр ИИН запрещает новые дубли; тест `test_shared_registry_migration_preserves_existing_duplicate_patients` проверяет сохранность старых дублей и времён приёма.
- После независимого просмотра исправлена гонка: если аудиозагрузка сохранила приём во время ожидания блокировки, пауза/завершение повторно читает сохранённый приём, а не работает со старым временным состоянием.
- Для уже начатой записи предусмотрено одноразовое окно отправки до 30 секунд после границы 15 минут. Это время доставки последнего фрагмента; пауза не меняет исходный срок записи.
- PDF использует структуру предоставленного бланка без переноса персональных данных и без утверждения, что это официально утверждённая нормативная форма.
- После завершения приёма архивное аудио загрузилось в браузер: длительность 57,3 секунды, `readyState=4`, `error=null`. Кнопок начала новой записи нет. Это подтверждает готовность архива к воспроизведению после закрытия приёма.
- В списке врача для проверяемого пациента осталось три консультации: две прежние и одна новая с данными. Прерванный пустой приём в список не попал.
- При ширине окна 390 px ширина документа и `scrollWidth` равны 375 px с учётом полосы прокрутки; горизонтального переполнения нет.
- Живой прогон с PostgreSQL включает 19 успешных проверок: работа двух врачей, разграничение доступа, времена начала и окончания, передача документа через [пример клиента МИС](../examples/mis_client.py), повторная отправка и отзыв интеграционного ключа. Запущенный [пример приёмника](../examples/mock_mis.py) дважды ответил HTTP 201 на один документ; повторная передача не создала новый документ.

## Воспроизведение автоматических проверок

```powershell
cd backend
../.venv/Scripts/python.exe -m pytest -q
cd ../frontend
pnpm test
pnpm build
```

Пройденный сценарий браузера: пустой поиск → поиск синтетического пациента по ИИН → компактная карта → повторный приём с выбранным предыдущим листом → пауза без новой записи истории → изменение общего согласия → возобновление → ручной черновик → загрузка 57-секундного синтетического аудио → завершение во время обработки → выбор J02.9 из справочника → сохранение → «Проверить» → «Проверено врачом» → PDF в отдельной вкладке → фильтр «Нужна проверка» в «Моих приёмах». Дополнительно подтверждены доработка старого черновика с истёкшим окном записи и прерывание пустого приёма через меню без появления листа в истории.

Локально подтверждены также сценарии второго врача, очистка поиска, переход к предыдущему приёму, длинное ФИО на двух размерах экрана и живая передача в пример МИС.
