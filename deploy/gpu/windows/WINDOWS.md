# GPU-ПК medhub: Windows и LM Studio

На этом ПК работают два отдельных процесса: ASR medhub на TCP **8090** и установленный LM Studio на TCP **1234**. Backend, worker и база medhub могут работать на другом компьютере. Для этого варианта Docker и Ollama не требуются.

## Состояние подготовки 30 сентября 2026

Получены изменения `origin/dev` до `618d47f`. Проверялся актуальный `app.providers.generate(segments, context, target)`: расширенные поля приёма, отдельные рекомендации по обследованиям и варианты диагнозов, правки врача, роли говорящих и длинный текст. Последующие изменения ЭЦП и интерфейса не меняли этот контракт. Текущий профиль production с OpenAI не переключался на локальную LLM.

**Whisper large-v3 + Community-1 технически совместимы с текущим ASR; ни одна из двух проверенных LLM не прошла проверку достоверности извлечения фактов.** Валидный JSON сам по себе не подтверждает пригодность модели для медицинских документов.

| Модель и профиль | Наблюдения на синтетических примерах | Вывод |
| --- | --- | --- |
| Whisper large-v3 `int8_float16` + Community-1, CUDA, batch 4 | Русская запись распознана; два системных голоса в английском диалоге разделены. При загруженной Qwen около 25 секунд аудио обработаны за 2,47 с, около 12 секунд русского — за 1,52 с на прогретых моделях | Подходит для технического пилота распознавания; качество казахской речи, реальных шумов и длительных приёмов ещё не измерено |
| Gemma 3 4B Q4, context 4096 | Три коротких ответа: 6,69–10,25 с, JSON валиден. В русско-казахском примере придуманы симптомы; правка длительности жалобы не соблюдена. Длинный запрос на 9233 токена отклонён HTTP 400 | Для текущего сценария не подходит |
| Qwen 3.5 9B Q4_K_M, context 16384, `reasoning_effort=none`, `max_tokens=2048`, `temperature=0.1` | Три коротких ответа: 5,92–7,48 с; длинный — 17,72 с. JSON валиден, длинный текст принят, часть правок соблюдена. Отрицание тошноты на казахском превращено в жалобу на головокружение/шаткость; роли пропущены, давление и пульс не внесены в предназначенные поля | Оставлена как экспериментальный API, не рекомендована для автоматического заполнения документов |

Это четыре синтетических сценария на модель, без статистической оценки качества. Длинный сценарий содержит повторяющиеся реплики и имитирует объём примерно 15-минутного диалога; он проверяет вместимость контекста, а не качество реального приёма. Режим Qwen с рассуждениями по умолчанию не завершил пробный запрос за несколько минут и был остановлен. Ограничение вывода в 2048 токенов тоже требует повторной оценки на более насыщенных записях. Сохранение ручного диагноза дополнительно обеспечивает `merge_generated_fields` приложения, поэтому его сохранность не следует приписывать только модели.

Полные результаты остаются локально в `artifacts/gemma-current-dev.json`, `artifacts/qwen-current-dev-fast.json`, `artifacts/qwen-asr-coexistence.json`; в Git они не включаются. Для повторения LLM-проверки используйте синтетический сценарий:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_local_models.py --url http://10.9.0.3:1234/v1 --model medhub-llm --reasoning-effort none --max-tokens 2048 --temperature 0.1 --long --output artifacts/local-model-check.json
```

Community-1 загружена после принятия условий владельцем аккаунта. Полный `/transcribe` проверен с `HF_HUB_OFFLINE=1`. ASR слушает `10.9.0.3:8090`: health и авторизованная транскрипция вернули 200, запрос без токена — 401. LM Studio `/v1/models` и `/v1/chat/completions` доступны через `10.9.0.3:1234`. **10.9.0.3 принадлежит этому ПК**: проверка с него не доказывает доступность с удалённого backend.

LM Studio слушает `0.0.0.0:1234` без аутентификации; на момент проверки все профили Windows Firewall отключены. Перед подключением backend требуется ограничить входящий доступ его VPN-адресом и настроить API-аутентификацию LM Studio. Сетевые настройки LM Studio и глобальный firewall в ходе проверки не менялись. Автозапуск после перезагрузки не установлен.

## Локальная конфигурация

Проверенное окружение: Python 3.12.6, PyTorch 2.8.0+cu128, torchaudio 2.8.0+cu128, faster-whisper 1.2.1, CTranslate2 4.8.2, pyannote.audio 4.0.7 и PyAV 15.1.0. Полный список версий сохранён в `requirements.lock` рядом с этой инструкцией. Для восстановления зависимостей в созданном `.venv`:

```powershell
.\.venv\Scripts\python.exe -m pip install uv
.\.venv\Scripts\uv.exe pip install --python .venv/Scripts/python.exe --index https://download.pytorch.org/whl/cu128 --index-strategy unsafe-best-match -r deploy/gpu/windows/requirements.lock
```

Python-окружение ASR находится в `.venv` в корне репозитория. Файл `deploy/gpu/windows/.env` содержит настройки только ASR и исключён из Git:

```dotenv
BIND_IP=10.9.0.3
ASR_PROVIDER=faster_whisper
ASR_DEVICE=cuda
ASR_COMPUTE_TYPE=int8_float16
DIARIZATION_BATCH_SIZE=4
ASR_RELEASE_CUDA_CACHE=true
ASR_MODEL=D:/AI/medhub/models/faster-whisper-large-v3
DIARIZATION_MODEL=D:/AI/medhub/models/pyannote-speaker-diarization-community-1
ASR_SERVICE_TOKEN=<случайный секрет длиной не менее 32 символов>
MAX_AUDIO_MB=80
```

Секрет должен совпадать с `ASR_API_KEY` на backend. Скрипты читают простые строки `KEY=value`, поддерживают значения в кавычках, пустые строки и комментарии на отдельных строках. Подстановка переменных и выполнение команд из `.env` не поддерживаются.

Из корня репозитория в PowerShell:

```powershell
.\.venv\Scripts\python.exe deploy/gpu/windows/check-runtime.py
.\.venv\Scripts\python.exe deploy/gpu/windows/check-runtime.py --cuda-test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/gpu/windows/start-llm.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/gpu/windows/start-asr.ps1
```

`--cuda-test` выполняет небольшое матричное умножение PyTorch и проверяет доступ CTranslate2 к GPU. Без этого флага диагностический скрипт не запускает GPU-вычисления. Веса моделей он не загружает. Код завершения 1 означает незавершённую подготовку, например отсутствие Community-1; незапущенный HTTP-процесс отмечается отдельно.

`start-asr.ps1` работает в текущем окне, останавливается через Ctrl+C и не устанавливает службу или автозапуск. Он использует один Uvicorn worker, добавляет CUDA DLL из `torch/lib` в `PATH`, отключает загрузку с Hugging Face при инференсе и метрики pyannote.

`start-llm.ps1` загружает установленную `qwen/qwen3.5-9b` через CLI LM Studio с идентификатором `medhub-llm`, контекстом 16384 и одним параллельным запросом. Параметры `-Model` и `-ContextLength` позволяют явно выбрать другой профиль, для которого нужно повторить измерения. Перед сменой модели под тем же alias выполните `lms unload medhub-llm`. Сам HTTP-сервер включается отдельно в LM Studio на TCP 1234. Скрипт не перезапускает сервер и не меняет его сетевые настройки.

В проверенном окружении `faster-whisper 1.2.1` используется с `av 15.1.0`: `av 19` оказался несовместим с этим конвейером. Предупреждение `torchcodec` об отсутствии shared FFmpeg само по себе не блокирует данный ASR: приложение декодирует запись через PyAV и передаёт pyannote готовый словарь с waveform и sample_rate. Работоспособность всё равно подтверждается полным `/transcribe`, а не отсутствием предупреждений при импорте.

## Загрузка моделей Hugging Face

Обе модели уже загружены на этом ПК. При восстановлении на другой машине нужно скачать обе: без Community-1 запрос `/transcribe` завершится 503, даже если Whisper установлен. `/health` при этом может отвечать `ok`: это проверка HTTP-процесса, а не моделей.

На [странице Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) должны быть приняты условия для аккаунта, которому принадлежит токен. Если токен передан локальным файлом `huggingface_token.txt` в корне проекта, загрузка выполняется без вывода его содержимого и без значения секрета в командной строке:

```powershell
Remove-Item Env:HF_HUB_OFFLINE -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe scripts/download_models.py --directory D:/AI/medhub/models --token-file huggingface_token.txt
```

Файл токена должен оставаться исключённым из Git; не копируйте его в документацию и логи. Альтернатива — интерактивный `.\.venv\Scripts\hf.exe auth login`, который временно сохраняет авторизацию в пользовательском хранилище Hugging Face; не добавляйте токен в Git credentials. Интернет нужен для первоначального скачивания пакетов и моделей; после загрузки проверяйте реальный инференс offline.

После установки обеих моделей перезапустите ASR и отправьте короткую синтетическую запись на `/transcribe` с Bearer-токеном. Ожидается JSON с `segments`, `speaker`, `start`, `end`, `text`. Только этот тест подтверждает загрузку моделей и выполнение полного конвейера. Не используйте реальные данные пациентов для технического тестирования.

## Память RTX 3060 12 GB

Проверенный профиль: Whisper `int8_float16`, один запрос за раз; для экспериментальной LLM — Qwen 3.5 9B Q4_K_M с контекстом 16384, идентификатором `medhub-llm`, одним параллельным запросом и без TTL. На этом ПК также оставалась загружена существующая embedding-модель около 639 MB. При ASR с загруженной Qwen выборка `nvidia-smi` каждые 0,5 секунды показала максимум 10041 MiB занятой VRAM и минимум 2075 MiB свободной. Это замеры коротких запросов, а не гарантия памяти при одновременном длинном LLM-инференсе и ASR.

Whisper и pyannote остаются в GPU-памяти после запроса. `DIARIZATION_BATCH_SIZE=4` уменьшает временные GPU-буферы, а `ASR_RELEASE_CUDA_CACHE=true` освобождает неиспользуемый кэш PyTorch между диаризацией и Whisper; веса при этом сохраняются. Без явных настроек код использует batch 32 и не очищает кэш, сохраняя прежнее поведение других установок. ASR блокирует второй ASR-запрос ответом 429, но не координирует память с LM Studio. Больший контекст, число параллельных обращений или другая модель требуют нового измерения памяти и задержек.

Профиль `medhub-llm` загружается **без TTL** и остаётся в памяти: после автоматической выгрузки этот пользовательский alias недоступен для JIT-загрузки. Для ручной выгрузки используйте `lms unload medhub-llm`; перед следующей генерацией снова выполните `start-llm.ps1`. Не загружайте дополнительные модели параллельно без проверки памяти. Auto-Evict управляет только моделями LM Studio и не выгружает ASR. См. [документацию LM Studio](https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict).

## Подключение backend через VPN

Backend worker должен видеть VPN-адрес GPU-ПК по TCP **8090** и **1234**. Браузеру врача прямой доступ к этим портам не нужен. На GPU-ПК разрешите входящие соединения только с VPN-адреса backend; не делайте публичный проброс портов.

На этом ПК `BIND_IP` уже равен `10.9.0.3`. При восстановлении используйте адрес фактического VPN-интерфейса; без него оставляйте `127.0.0.1`. Настройте интерфейс прослушивания LM Studio и его API-аутентификацию отдельно. Доступ для администрирования организуется отдельно от API моделей.

На компьютере с backend medhub ASR можно подключить следующими параметрами. Секция LLM предназначена только для экспериментального стенда после ограничения сетевого доступа; рабочий provider нельзя переключать на основании одной проверки JSON:

```dotenv
ASR_PROVIDER=self_hosted
ASR_URL=http://<VPN-IP-GPU-ПК>:8090
ASR_API_KEY=<тот же ASR_SERVICE_TOKEN>
INSTALL_LOCAL_AI=false
LLM_PROVIDER=openai_compatible
LLM_URL=http://<VPN-IP-GPU-ПК>:1234/v1
LLM_MODEL=medhub-llm
LLM_API_KEY=<API-токен LM Studio>
LLM_RESPONSE_FORMAT=json_schema
LLM_REASONING_EFFORT=none
LLM_MAX_TOKENS=2048
LLM_TEMPERATURE=0.1
LLM_IS_CLOUD=false
```

Суффикс `/v1` в `LLM_URL` обязателен. LM Studio требует `LLM_RESPONSE_FORMAT=json_schema`: вариант `json_object` в проверенной версии сервера возвращает 400. Если модель загружена под другим идентификатором, замените `medhub-llm` в настройках backend. Не копируйте backend-профиль `ASR_PROVIDER=self_hosted` в окружение GPU-сервиса. После изменения backend-настроек перезапустите API и worker, затем проверьте короткий синтетический сценарий: распознавание → заполнение листа. Проверяйте ответы JSON, разделение говорящих и потребление памяти; одного HTTP `/health` недостаточно.

`LLM_REASONING_EFFORT`, `LLM_MAX_TOKENS` и `LLM_TEMPERATURE` применяются только к `openai_compatible`. Без явных значений эти параметры не передаются; настройки существующих облачных провайдеров сохраняются. Для Qwen в OpenAI-совместимом API проверено `reasoning_effort=none`, значение `off` сервер отклоняет. См. [формат запросов LM Studio](https://lmstudio.ai/docs/developer/openai-compat/chat-completions) и [структурированные ответы](https://lmstudio.ai/docs/developer/openai-compat/structured-output).
